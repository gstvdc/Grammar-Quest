# Main Menu Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the direct laboratory launch with a pixel-art RPG main menu that selects the game mode, exposes options, and keeps the formal grammar workflow intact.

**Architecture:** Keep navigation and user preferences in `AppState`; rendering remains in the game crate. Add focused `ui::main_menu` and `ui::options` modules that return small action enums, while `app.rs` owns frame dispatch and process exit. The existing editor becomes mode-focused, consuming `state.play_mode` but no longer mutating it.

**Tech Stack:** Rust 2024, macroquad 0.4.16, egui 0.31, egui-macroquad 0.17.3; existing embedded Press Start 2P font and sound assets.

**Spec:** `docs/superpowers/specs/2026-09-15-main-menu-design.md`

## Global Constraints

- Change only `crates/grammar_quest`; `grammar_engine` remains dependency-free and its public behavior unchanged.
- Preserve the seven graded requirements and the shared `ui::side_panel` surface.
- Add no dependencies; use macroquad primitives and the bundled Press Start 2P font.
- Use `ScreenMode::MainMenu` and `ScreenMode::Options`; `AppState::new()` must start at `MainMenu`.
- The menu must use the approved 16-bit RPG language: deep purple, gold accents, red title outline/shadow, simple geometric mascot, and rising gold sparks.
- The laboratory must expose only the mode chosen from the main menu. Returning to the menu is the only way to change mode.
- Volume is in-memory only, default `1.0`, clamped to `0.0..=1.0`, and passed explicitly to sound playback.
- Run `cargo fmt`, `cargo build --workspace`, `cargo clippy --workspace --all-targets`, and `cargo test --workspace` before completing the work.

### Task 2: Pixel-art menu renderer and mode selection

**Files:**
- Create: `crates/grammar_quest/src/ui/main_menu.rs`
- Modify: `crates/grammar_quest/src/ui/mod.rs`
- Modify: `crates/grammar_quest/src/app.rs`

**Interfaces:**
- Consumes `AppState`, `MainMenuStage`, `PlayMode`, `Sfx`, and the loaded `Font`.
- Produces `MainMenuAction::{None, OpenModeChoice, SelectMode(PlayMode), OpenOptions, Quit, Back}`.
- `app.rs` maps each action to the `AppState` methods from Task 1; only `Quit` breaks the run loop.

- [ ] **Step 1: Add the module contract before the renderer**

  Export `pub mod main_menu;` in `ui/mod.rs`. In `ui/main_menu.rs`, define:

  ```rust
  #[derive(Debug, Clone, Copy, PartialEq, Eq)]
  pub enum MainMenuAction {
      None,
      OpenModeChoice,
      SelectMode(PlayMode),
      OpenOptions,
      Quit,
      Back,
  }

  pub fn show_main_menu(
      state: &AppState,
      font: &Font,
      sparks: &[Vec2],
      time: f32,
  ) -> MainMenuAction;
  ```

- [ ] **Step 2: Implement the approved macroquad composition**

  Draw the background, a low-opacity star field, and each supplied spark in gold. Center the title `GRAMMAR` / `QUEST` using `measure_text` and `draw_text_ex` with Press Start 2P; draw a 3px dark-red offset outline first and gold foreground second. Draw a static mascot entirely from `draw_rectangle`, `draw_triangle`, and `draw_circle`; do not load the neon logo or swordsman sprite.

  Render root controls as 16-bit framed hit rectangles: `▶ JOGAR`, `OPÇÕES`, `SAIR`. In `ChooseMode`, render `MODO LIVRE`, `MODO ENIGMA`, and `← VOLTAR`, each with concise explanatory copy. Use mouse-hit testing against the same rectangles and return the corresponding `MainMenuAction`; use `Escape` only for `Back` while selecting a mode. Apply a 1–2 px bob to the mascot from `time.sin()` and no frame-by-frame sprite animation.

- [ ] **Step 3: Load the font and wire menu frame dispatch**

  In `app::run`, load the embedded font once:

  ```rust

      "../assets/fonts/PressStart2P-Regular.ttf"
  ))
  .expect("embedded Press Start 2P font is valid");
  ```

  Replace the single laboratory/playing match with branches for `MainMenu` and `Options` (Options is wired in Task 4). Call `show_main_menu`, play the click SFX with `state.master_volume` for non-`None`/non-`Back` actions, map actions to Task 1 transitions, and set a local `should_quit` only for `Quit`. Update Escape handling so Laboratory calls `back_to_main_menu`; Playing/Won still call `back_to_lab`; MainMenu Root does not quit through Escape.

- [ ] **Step 1: Make audio volume explicit**

  Change the SFX API and helper to:

  ```rust
  pub fn play_click(&self, volume: f32) { play_once(&self.click, volume); }

  fn play_once(sound: &Sound, volume: f32) {
      audio::play_sound(sound, PlaySoundParams {
          looped: false,
          volume: volume.clamp(0.0, 1.0),
      });
  }
  ```

  Apply the same parameter to the three other public SFX methods. Update every use in `app.rs`, `gameplay.rs`, and `ui/game_hud.rs` to pass `state.master_volume`.

- [ ] **Step 2: Create the options panel**

  Add `ui/options.rs` with `OptionsAction::{None, Back}` and a `show_options(ctx: &egui::Context, state: &mut AppState) -> OptionsAction` function. Apply the existing `ui::theme`, render a `VOLUME` slider bound to a local `volume`, call `state.set_master_volume(volume)` after it changes, and show the percentage as `format!("{}%", (state.master_volume * 100.0).round())`. Render `CRÉDITOS` from:


  inside `egui::ScrollArea::vertical()`. A `← VOLTAR` button and Escape return `OptionsAction::Back`.
